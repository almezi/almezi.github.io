# Featured projects → carousel

## Context
The "Featured projects" section (`src/pages/index.astro:61-84`) renders projects in a static `.project-grid`. You want it to be a swipeable, Cupertino-style carousel. Per your choice: **multi-card carousel** — 1 card per slide (+ peek of next) on mobile, 2 cards side-by-side per slide on desktop. Zero dependencies — native scroll-snap, matching the site's setup and iOS design language.

Existing `.project-card` markup and styles stay untouched; they get wrapped in carousel slides.

Note: with the current 2 projects, desktop shows both cards in one page, so the controls auto-hide there (it looks like today's grid). On mobile both cards become swipeable pages. The script computes pages at runtime, so it adapts automatically if more projects are added later.

## Changes

### 1. `src/pages/index.astro`
Replace the `.project-grid` wrapper with:
```html
<div class="carousel" aria-roledescription="carousel" aria-label="Featured projects">
  <div class="carousel-track" tabindex="0" data-carousel-track>
    {projects.map(...) => (
      <div class="carousel-slide" role="group" aria-roledescription="slide" aria-label="{n} of {total}">
        <article class="project-card">…existing card markup, unchanged…</article>
      </div>
    )}
  </div>
  <div class="carousel-controls" data-carousel-controls hidden>
    <button data-carousel-prev class="carousel-btn" aria-label="Previous projects">←</button>
    <div class="carousel-dots" data-carousel-dots></div>
    <button data-carousel-next class="carousel-btn" aria-label="Next projects">→</button>
  </div>
</div>
```

Add a `<script>` to the page (Astro bundles it, same pattern as the tab script in `Base.astro`):
- Compute pages from `slides[0].offsetLeft`/widths; derive cards-per-view from slide vs track width (1 on mobile, 2 on desktop).
- Prev/next buttons scroll by one page via `scrollTo({ left: slide.offsetLeft, behavior })` — `behavior: "smooth"`, or `"auto"` when `prefers-reduced-motion: reduce`. Buttons disable at the ends.
- Dots (one per page) are built by the script as buttons with `aria-label="Go to projects page n"`; active dot gets `aria-current="true"`. Clicking a dot scrolls to that page.
- Track `scroll` event updates active dot + disabled states; `resize` (and initial load) recomputes pages and toggles the controls row hidden when everything fits in one page.

### 2. `src/assets/style.css`
- `.carousel-track`: `display:flex; gap:1.5rem; overflow-x:auto; scroll-snap-type:x mandatory; scrollbar-width:none` (+ `::-webkit-scrollbar { display:none }`).
- `.carousel-slide`: `flex: 0 0 100%; scroll-snap-align:start; scroll-snap-stop:always; display:flex` and `.carousel-slide .project-card { flex:1 }` for equal-height cards; at `min-width: 768px` slide basis becomes `calc(50% - 0.75rem)` for two cards per view.
- `.carousel-controls`: centered row of round Cupertino buttons (44px, white bg, subtle border like `.btn-secondary`, disabled → 35% opacity) with dots between them.
- `.carousel-dot`: 0.5rem slate dot; active = teal (`--color-brand-primary`), slightly widened (App Store page-control feel).
- Remove `.project-grid` from the shared `.project-grid, .skills-grid` rules (base + 768px block) since it's no longer used.
